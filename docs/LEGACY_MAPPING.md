# 旧档案映射与迁移

入口为「管理 → 旧档案映射」。这是 v1.5.0 / M4 的显式迁移工具。它读取完整账本内一直保留的 `project_data`、`sub_project_data`、`item_data` 及其关系，不根据列表名字猜测团体或同一人。

旧手机系统备份、工程恢复包与 App 完整备份的封装不同。需要带入其他旧账本时，先按[恢复指导](RECOVERY.md)校验并制作兼容的完整包，再使用既有恢复预检；本页面不接收任意裸 SQLite 文件，也不在当前账本上盲目拼接另一个库。完整恢复是独立的整代替换，须先保护当前账本。真实迁移须另获对应范围授权。

## 操作顺序

1. 读取旧档案。原日期、原类型、原金额和完整原文可查看，原始表不编辑。识别到既有迁移来源的行会显示「已有来源记录」，不会再次新增或覆盖用户后续修改。
2. 在未迁移行填写映射。业务信息默认未知，可全空保存；也可跳过某行，继续保留在原档案。先在成员管理建立所需身份，再选择稳定成员；不按同名自动建人、合并人或继承团体。
3. 若已确认整批含义，可展开批量规则：每行一张、原日期中的年月日、全部已领取，以及每个原列表对应成员、每类原类型对应尺寸/属性。规则默认均未选，只更新所选字段；应用后逐条检查。无效原日期保留原文，不变成今天。单条还可调整多人、张数、日期、四项勾选属性、领取提示及备注。部分领取的批次数量/实际时间可随后在记录页补齐。
4. 生成隔离预览。确认新增条数、已有来源、未选原行及各条信息；可以导出完整 JSON 差异报告到自己选择的位置。报告包含原文，应按个人数据保存。
5. 「核对并迁移」再次确认后才提交完整账本代。返回调整或取消确认不写当前账本。原始四表、原 ID、金额文本、ext、NULL、未知列、二进制、设置、序列和附件继续保留，迁移前完整代也保留。

## 数据边界

- 新 Cheki 使用新领域稳定 ID，与旧行 ID 分开；`legacy_raw` 保留旧行，`legacy_archive_context` 保留当时项目/列表原行，`legacy_source` 记录明确映射及批次。新建动作时间是迁移制作动作，原发生日期只取明确映射，原动作/扩展原文不覆盖。
- 通用来源的 `price` 独立保留原文，不能擅自解释为金额、单价、张数、购买或库存。此前用户确认的特定快照金额政策仍按原有稳定来源生效。它的每行一张、带签三寸、全部已领和背签例外不会推广到任意旧库。
- 领取未知不默认未领取，已领也不虚构实际领取时间。背签仅在明确带签时可勾选，未知与 false 分开；各业务字段持续可空。已填写格式、成员关系、同人约束等仍校验。
- 相同已识别来源精确比对原文后跳过；原文冲突、重复来源或相同旧 ID 出现无法识别的来源记录时，整批停止，先人工核对。现有记录只能在记录页修改，不借迁移重写历史。
- 只追加明确选中的 Cheki 及其审计，不生成券、购券、库存、消费或成本关联；不物理合并/删除旧逐张行，日常合并显示逻辑不变。

## 实现与验证

`LegacyMappingStore.read` 捕获完整一致快照，在自有隔离副本升级 schema1–8 后只读。映射使用相同捕获代，整批事务通过既有记录服务与审计写入隔离库。完整业务和外键校验、闭库/WAL 检查及再封装后，交 `BackupStore` 的完整代切换协议。未改当前 schema8，恢复、CSV 与 Python 校验继续携带新增来源元数据。

预览绑定数据库、全部文件与设置；制作期间或确认前当前账本改变均拒绝。隔离文件被修改也拒绝。触发器/虚拟表扩展可以只读查看，但映射写入前拒绝，避免未知逻辑修改原档案；不删除扩展来绕过。自有未使用预览可清理，之前真实代和备份不删。

本地验收使用合成数据库及隔离副本，覆盖 342 条原行、空信息、显式映射、幂等/冲突、过时预览、完整恢复、设置附件、原始序列和进程中断。电脑 Flutter 窄屏/大字/键盘检查不能替代 Android 的文件页、原位升级、实际迁移、冷启动或用户阶段验收。实际结果见[本包交付](acceptance/V150_HANDOFF_20261015.md)，当前状态以 MasterSheet 为准。
