## 数量与日期

`BiStore.read()` 在一个 SQLite 事务内读取记录、身份/原颜色兼容、尺寸、券对象及真实消费和换送绑定。`BiSnapshot.report()` 派生指标，不写汇总表，不改 schema 8。读失败可重试；记录、券或管理的成功提交刷新统计。页面、条形占比、日期趋势、明细和 CSV 均使用同一报告。

实际张数按记录数量计一次；成员数量按符合筛选的身份关系计算。A 单切 3、B 单切 2、AB 合影 2，得到 7 张、9 次参与，A=5/9、B=4/9。只选 A 时为 5 张和 5 次 A 参与，不能继续把 B 算进分母。Person 视图用明确的 Person ID 去重，跨身份名称与原行保留。停用身份仍可统计。

日期只读 `occurred_on`，不从录入动作或领取时间补造日期。周一开周、上海业务日沿现有 UI 暂行，最终选择按 DEC-010/059 待检查；自然月、自然年，闰日和跨年周分别验证。“所有”包含无日期记录并另列日期未知；期间统计排除无日期，不把它归到今天。

张数未知不算零；成员、尺寸、属性、领取等各按已知输入统计，缺失另列。空范围的数量为 0、比例为“—”；只有未知张数的条目显示未填写。属性分类中未知单列，背签不作为第四个互斥分类。领取状态按记录张数分布，已领/待领数量另用真实批次，未知批次不推断为未领。

成员图形取当前设置色，包括已确认迁移资料的稳定身份兼容继承；文本保持深色，中性描边支持白色等低对比设置。当前标签不倒写历史名称快照。日期修改会重分期间；领取修改不移动发生日。下钻修改后按原日期与筛选重新检查，不保留错误期间的行。

## 库存、流量与金额

期间购买、拍切消耗、赠送、交换入/出、调整入/出分别列出。库存调用既有 `remainingLots`，回放至所选期间末日；“所有”的库存截止查询当天，未来已记账流水仍属于所有期间流水，页面明确区别。截止日含当天；可用、长期/限时、临期和过期数量从同一剩余来源派生，提醒天数复用券设置。无限时库存不出现限时零栏，仅长期时省略长期标签。草稿不进入实际库存或金额。

购券总额和各券种金额只计 `purchase`，赠送/交换不再增加支出。购入均价用已知成本对应的已知购入张数作分母，未知成本张数另列。库存成本与出库成本来自原来源及不可变分配，交换继承成本不平均抹平。金额继续 DEC-049 的十进制原文和精确比例，例如 10/3；不冻结整数分、权威总額或舍入策略，不重算历史。混合已知/未知成本显示已知部分及未知张数，不能把部分合计当完整金额。

券金额、流量和库存按期间与团体筛选。成员、Person、尺寸、属性、领取等 Cheki 筛选不把团体通用券强行分摊给人；“所选 Cheki 的实际用券成本”只计匹配记录真实绑定的消费。未用券、仅记录或旧价格不据此推算 Cheki 价格。筛选扩展后两者的边界直接显示在成本区域。

## 统计 CSV

保存时只打开系统目的地选择器，内存字节直接写所选文档；不先在 Downloads 或 App 目录生成额外过程文件。不自动连接 NAS、上传或后台导出。实际目的地由用户选择的文件提供器决定，集中 Android 验收仍须检查该提供器。取消或失败不写账本、不宣称保存成功。

CSV 使用 UTF-8 BOM、CRLF、RFC4180 引号，包含当前筛选元数据、数量和缺失指标、成员/Person及尺寸分布、分类、每日、原记录、各券种购入及均价、期末存量、流量汇总和原流水。`section` 区分各统计表；数量和比例分母分别保留，金额使用精确比例，未知金额留空并保留未知张数。用户文字的公式前缀作表格防护，原 JSON 仍保留原文、ID、动作戳和未知字段。CSV 与筛选报告对账，不使用显示百分比舍入去回算数量或金额。

统计 CSV 不是完整恢复格式，也不是 M4 的多表导入模板。完整数据库、原档、谱系、设置、序列、附件与适用事务文件仍通过已有完整备份恢复。M4 批量携带与通用旧映射没有在此包开始。
