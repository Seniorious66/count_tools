# 记录删除与直接支出

v1.5.1-r8 的实现说明。交付状态和实际验证以 MasterSheet 及本包交付报告为准。

## 使用方式

记录详情的「删除记录」只影响这一条；合并记录页的「删除整组记录」影响确认框列出的整组条目。确认框显示条数和张数，取消不保存。存在关联扣券时一并撤销，退回原来源批次和原期限，已过期券继续过期。首页、记录、数量与花费统计同步排除删除项。删除保留审计，不物理清除原数据；本版没有日常撤销删除入口。

用券只有「记录并扣券」与「仅记录」，各占一半宽度。仅记录可填「实际总支出（元）」，是这条记录的总额，不乘张数，也不增加或消耗券库存。空金额保持未知，明确 0 保留为 0，内部保存完整十进制，显示四舍五入到元。多人和跨团费用沿既有共同费用规则保留一次，不自动平摊或重复到每个成员。

主动勾选宿题会切到仅记录；可以再手动选择扣券。离开宿题保留当前方式。仅打开既有宿题记录不改变用券、支出、领取或库存。旧未知用券方式可以仍然没有选中项，保存时不自动补为扣券或仅记录。

## 数据与维护约定

- schema 9 仅追加 `record_void_direct_expense_v1` 版本账本，不改写既有记录、券或历史。旧 schema 1–8 仍先校验，再在隔离副本升级。旧程序不支持 schema 9，不得降级打开。
- 逻辑删除写入 `RecordInformation.voided`（动作时间、操作 ID、删除前 revision），原业务内容逐值保留，原行保存在记录修订审计。`EntryStore.deleteRecords` 在一个 SQLite 事务中撤销当前扣券、追加记录与 Entry 审计；整组冲突、异常或写入失败全部回滚。相同操作和范围重放不重复退券；过期 revision 或改变重放范围拒绝。
- 当前费用来源保存在 `CouponPlan.expense_origin`。明确直接支出使用 `direct` 和可空 `direct_amount`，扣券使用 `coupons`。只有主动选择或输入才为旧记录确定新来源；无关编辑保留旧来源及已确认旧金额。当前费用互斥，原始金额和旧操作保留在审计里。
- `RecordStore`/`BiStore` 的有效查询排除作废记录；成本、花费、CSV 和所有统计共用同一结果。原始 SQL 表、记录历史、完整备份和结构化携带仍包含作废记录及所有关联，不能在导出时丢掉删除状态而令记录复活。
- 维护者如需读取已删除条目，使用原始记录表和修订审计进行只读检查。不要直接改 `voided`、删除审计、编辑绑定消费或操作真实用户库来模拟恢复。

完整备份含全库、历史、序列、设置与附件。Dart 与 Python 校验器同步识别新状态，旧结构化携带包只在隔离组装库补版本账本后校验。导入同 ID 不同内容仍整批拒绝，不能用旧包覆盖当前删除状态。安装、真实恢复与用户功能验收须有当轮明确授权，自动开发不操作设备或 NAS。
