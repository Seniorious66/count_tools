# UI 修复记录

## UI-FIX-001：限时券按库存显示

2026-10-11 · WF-012。用户要求单列 UI 修复，放在 M1 前；限时活动较少，没有限时库存时不在其他页面显示「限时券 0」。

- 首页按当前可用限时券总量判断：为 0 时不显示限时数量、空临期提醒，也不标「长期」；直接显示可用券总数。
- 登记按所选券种判断：限时池为 0 时不显示限时扣量栏，唯一池用「可用 N」；扣券明细始终展开。隐藏的限时扣量为 0，库存不足仍拦截。
- 核对只列实际使用的非零券池。只有长期池时直接显示券名和张数，不标「长期」；某券种没有限时券，不受另一券种的正限时库存影响。券库和详情只有长期可用库存时也只显示数量或「可用」。
- 有可用限时库存时继续显示数量、截止日与分配栏，保留优先建议和独立手调。耗尽或到期后刷新展示。
- 券库、过期列表、历史流水与已有记录保留真实期限及正扣量；不因为现在库存为 0 隐藏过去的使用。未知或加载中的库存不能当作 0。

设计修复编号 UI-FIX-001 对应 WF-012，作为 M1 界面工作前置，`v1.2.0` 依赖 `WF-012`。M1 用合成库存 fixture 检查公共组件展示契约，未接入的券功能仍隐藏或禁用；M2 的 `v1.3.0/v1.3.1` 接真实库存与扣券时复验。此修复不触发 App 产品升版，不新增主线业务包；阶段状态及估算以 MasterSheet 为准。

原型 [混合库存](../ui/cheki-ui-prototype.html) 与 [仅长期可用库存](../ui/cheki-ui-prototype.html?tickets=long-only) 使用合成数据。检查首页、券库、登记、核对和返回；切换券种、成员、张数、恢复自动，验证正库存可分配、0 库存隐藏、不足仍阻止确认。刷新重置，不改变真实手机或库存。
