# Cheki 属性与扣券明细修订

2026-10-11，WF-010。用户本轮指示取代 [WF-009 登记规则](CHEKI_ENTRY_20261011.md) 中签名/宿题组合及明细折叠条款；其他日期、成员、领取和默认扣券规则继续有效。规划状态以 MasterSheet 为准。

## 1. 三项互斥与背签条件

属性以勾选形式显示「无签」「有签」「宿题」，必须且只能选一项，快捷新建默认有签。选择另一项自动取消原选项；再次点击唯一已选项保留它，不能留下全不选状态。

「背签」另设勾选，仅有签时可用。切换到无签或宿题立即清除背签并禁用控件；切回有签重新启用，但不自动恢复背签。有效组合只有无签、有签、有签+背签、宿题。属性不决定领取状态、领取时间或额外券消耗。

真实模型建议用 `signature_kind=unsigned/signed/homework` 枚举加 `back_signed` 布尔，并在存储、模型及服务层约束背签只能搭配 signed。HTML 原型暂用原布尔字段映射这三个合法状态；不是已冻结的 SQLite schema。

核对、详情、记录列表、编辑均显示同一分类。返回记录及编辑载入合法原值，不用新建默认值覆盖。统计中无签/有签/宿题为互斥分类，背签为有签子集，不能充当第四个互斥类别；日期归属继续按发生日期。

## 2. 扣券明细常开

新建默认扣券，扣券明细直接展开，无折叠按钮。修改成员/张数/券种、恢复自动建议及从核对返回后仍展开。券种团体前缀、逐池独立手改、共享库存汇总及差额拦截保留。

主动选择「仅记录，不扣券」时隐藏无关扣量字段；切回扣券立即展示明细。已有记录编辑仍保留原券关联，正式原子纠错由相依包实施；本轮不将合成演示升级为真实库存扣减。

## 3. 历史与实施检查

原需求曾允许签名与宿题组合或无签背签。保留原需求、已结束 ROUND 及原数据属性；真实迁移/导入遇冲突组合先单列待映射、显示原值和目标差异，不能按布尔优先级自动清除事实。未知历史不能套默认有签；备份保留原属性、ID、ext、未知字段与来源。

验收：新建恰选有签，背签可选；勾背签后分别切宿题/无签，背签清除且禁用；切回有签不暗恢复；唯一选项不能取消成空；返回/新建确认/编辑分类一致。扣券明细无折叠，返回和数量变化仍显示；独立池差额阻止继续；窄屏无横向溢出且核对按钮可达。

本轮仅 HTML 合成原型、规范与规划；Flutter、真实 schema、数据库迁移/恢复、手机及阶段验收均未实施。
