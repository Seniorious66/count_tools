## 已确认的金额显示规则

用户本轮补充：**“保留浮点数，只显示四舍五入”**。理解为保留非整数金额，**仅显示四舍五入到元**，不在数据库、成本继承或汇总中先取整。继续复用现有十进制原文及 `TicketMoney` 精确比例，避免为了“浮点数”改成有误差的二进制double；这不裁决此前总额/余分的全部金额终局政策。

- 赠送金额 = 每个实际扣减来源的单张冻结成本 × 该来源实际赠送张数，再求和。不能用券种现价或整个池子的均价替换多批次来源。
- 先合计精确数额，再对这一个显示结果四舍五入。明细、成员、团体和总计分别格式化，不能把已显示的整数相加作为总计。正金额恰为 `.5` 时向上显示；不改写原始成本。
- 例：来源100元/3张，送2张，内部仍为200/3，显示67元；不能先把每张显示33元再得66元。显示明细与总计可因分别舍入相差1元，不用改数据抹平。
- 未知金额仍留空/破折号并提示有缺失，明确0仍显示0；不能把已知部分标成完整总额。
- 普通花费视图使用统一显示规则；审计、精确金额导出及完整备份保持原值，不能把四舍五入后的展示写入普通CSV的精确金额列。

## 1. 每成员及每团体花费入口

统计页新增清楚的“成员花费 / 团体花费”入口。默认继承当前日/周/月/年/所有范围，成员行保留团体前缀及设置色。每行点击可看合计、Cheki花费、赠送消耗和按发生日期倒序的原始明细；可回到原记录或赠送流水。成员现有每日张数下钻也提供花费入口，不新增一套互不相干的金额算法。

**消费花费 = 既有Cheki实际花费 + 赠送实际来源成本**。购券付款、剩余库存价值单独保留，不能再加进消费花费造成重复；交换出入均不在发生时增加消费花费，之后实际Cheki/赠送才确认消耗。不新增现金输入，也不造历史购券或库存。

- Cheki有成员级消费绑定时按实际绑定归属；指定旧映射的单成员记录用已确认原price，每个原记录ID仅一次，合并展示不加倍。
- 赠送按转出券归属：个人券进其所属成员及团体；团体券仅进团体合计，不猜收券人或强行分摊给成员。成员页面不能把团体通用券直接归为某个人。
- 团体券用于Cheki且已有明确成员消费绑定时，按该绑定计成员；同一消耗同时进入成员及其所属团体是两个维度，不能把两个维度再相加。
- 旧多人/跨团记录若只有整条金额、无成员级来源，保留共同费用及原总额。单团多人可归团体一次；跨团共同费用独立列出。成员可查看相关共同明细，但不把整笔金额复制给每个成员或擅自平均分。**共同费用最终分摊方式等待用户检查，不阻其余确定归属统计。**
- 历史归属优先用原消费快照/审计；没有原归属且采用当前稳定身份展示时需明确派生来源，不能因改团体就悄悄改写历史。真实转团继续新身份，已有纠错审计不移除。
- 花费入口以自己的时间及成员/团体范围为准。只适用于Cheki的属性/领取筛选不能悄悄把赠送消耗排除；若从现有筛选进入，明确继承的有效条件，不用不适用的字段过滤赠送。
- 同一报告派生列表/详情/合计和适用导出；空数据、未知金额、重复关联、多人和修改后刷新均覆盖。

## 2. 张数与所需、扣池量联动

“先选成员→默认券或手动选券→修改张数”都要更新。新建例：1张变3张，对应成员需要3张；所选券种保持，自动池分配重新分配3张；改回2张时归还预占量并同步为2。

- 自动分配沿既有发生日、尺寸属性硬匹配、个人优先、有效期/FIFO。多人共享池必须统一预占，不能每个人各自看到整池库存。
- 选过券种不代表锁死旧扣量。手动选的券种保持；只要池数量仍由自动分配管理，张数变化应重新分配。
- 真正手动改过多行/多池数量时保留选择，不悄悄覆盖拆分。标出新的需要量、已分配量和差额，提供明确的重新自动分配操作；不可带着不等额计划实际入账。
- 库存不足用文字提示，例如“需要3张，可用2张，还差1张”，并允许改张数、券种或仅记录。不要异常堆栈、静默把3改2、跨券种/跨尺寸拼扣、借未来库存或自动允许过期券。
- 改成员、发生日、尺寸、属性和连续点按要使旧异步结果失效；核对页和保存校验使用最新计划。不能重复扣券。
- 编辑已保存记录的张数须显式生成修改计划并按既有事务/修订规则核对；不能因表单打开/自动联动就更改已冻结成本。已有下游依赖仍拦截，失败原记录/库存/成本均不变。

## 3. 赠送与换券成本

赠送已扣库存的事实不再执行一次扣减，仅在新消费报表里按已有不可变来源分配取值。赠送不增加Cheki张数或参与次数。历史赠送如有完整来源可只读派生纳入；缺成本不补0，不回写旧流水。交换继续逐来源成本守恒及原购入谱系，按已确认交换发生日和操作顺序入目标FIFO。

如因新读模型或默认分配增加字段，实施必须同时覆盖模型、存储、schema兼容、Dart/Python完整恢复、CSV/携带、序列/审计和隔离往返；不能只改页面或重写旧历史。

## 4. 高频换券默认

- 从券详情进换券保留来源券种；选定来源后自动读取该发生日实际可用池。只有一个有效池直接选；多个池按既有期限优先/FIFO顺序给稳定建议，核对页显示实际来源。
- 暂行保守边界：沿现有单来源池操作。优先最早到期的有效池；若该池不足，提示需要/可用/差额，并给其他池选择，不默默跨池拆单、切其他券种或跳过FIFO。多池自动合单不在未确认的存储语义下暗中实现。
- 新建目标默认**长期、截止日期为空、确认后计入库存**；选择限时后才需要截止日。目标券种仍由用户选择，不猜换到谁的券或自动创建券种。
- 来源与目标新默认只作用新建/未触碰的建议；用户手动选择、旧记录空字段、历史编辑不套默认。改券种/日期/数量时刷新库存与核对，旧异步读不能覆盖新选择。
- 默认入库仍经过核对与事务预检，主按钮清楚表示确认入库；保留显式存草稿/可空条目路径，不把旧草稿自动入库。一次确认只产生一次换券，入出同成同败。

## 5. 记录和购券张数加减

复用一个步进组件，保持数字输入、清空与单位“张”；左右为减/加，单点准确变化1，不靠长按。数量1时减号禁用，不生成0或负数；空值保持未知，点加号变1，空值减号禁用。清空仍可保存可空条目；非法输入先提示，不将其当0后执行步进。

按钮具备“减少一张/增加一张”的语义、足够触控区域，320–430竖屏及200%字体不挤掉输入与单位；编辑原值不变。记录步进与键盘输入走相同的数量/领取批次/扣池同步路径；购券步进更新核对与内部总额/数量比，不自动改用户输入总金额。调整库存的负数业务不复用正购券下限强行限制。
