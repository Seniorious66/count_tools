## 1. 有下游的购券成本更正

用户同轮追加明确方案：**“直接联动就可以了，不要阻止，按照计算规则继承上游改就行了。”** 本条取代本轮早先独立更正入口/额外影响确认的分析提案。用户直接在原购券记录修改金额，沿原有编辑/保存路径提交，下游自动按来源规则更新；不增加专门的成本更正入口、额外确认页或逐下游选择，不要求先撤销送券、消耗或交换。

- 只改这笔购券的有效总金额。原购券数量、日期、券种、归属、期限、已入库状态以及下游数量、来源选择、FIFO顺序、记录/领取事实全部保持。与成本无关的结构性编辑继续沿既有依赖拦截，不直接删除通用保护。
- 以原购入数量计算新单张成本，沿已存在的逐来源分配传播到直接消耗、赠送、剩余库存及所有交换后代；混合来源仅改变对应贡献。交换仍只继承成本，不额外产生购券或消费。
- Cheki/赠送的花费、成员/团体/期间统计、购券金额及均价、库存价值、核对预览与适用导出使用同一有效成本；数量和库存余额在更正前后逐项相同。旧原始映射price且没有这笔购券来源的记录不受影响。
- 采用追加式金额更正/撤回更正记录，保留原金额、原始分配与冻结引用、旧修订、原ID/created_at/ext/未知字段；原始审计可重建。当前有效金额由已确认更正派生，不原地抹掉旧账、不撤销重建实际库存流水。具体新增存储形态在实施前评估，但不能省略完整来源链支持。
- 修改金额的正常核对显示仍沿原流程，不另加影响审核门槛；后台算完整来源链，不把未知贡献推成0。更正动作有独立时间戳；统计仍归原业务发生日期，不将差额记成今天一笔新购券/新消费。
- 连续更正基于最新有效修订；再次改回旧金额同样走原编辑保存，后台追加审计，不增加独立撤回更正流程。重复保存幂等，同一事务内读最新链并计算，避免只更新半条链。不得沿用“存在下游”或“冻结成本”作为金额修改拒绝理由。
- 整笔原子提交。故障、取消、断进程或校验不通过时不留下部分更正。谱系缺失、成环或无法验证的链只阻止该笔，显示具体原因，不能猜测对应关系、无限等待或影响其他功能。
- 新持久信息必须贯通schema兼容、Dart/Python备份与恢复、完整快照/交易携带、稳定ID/冲突/重复处理、历史读回及缓存刷新；旧备份没有更正时等价于原金额。隔离恢复失败不替换原库。不强行承诺仍为schema8，也不把旧格式未覆盖的新信息丢掉。

该项是在旧DEC-050“有下游不修改”的规则上新增用户已明确的**金额编辑自动联动**例外，不能扩大为重排库存、改历史张数或级联删除授权。实现中采用原字段同步还是追加有效成本覆盖，必须保证当前查询/编辑/下游同源、完整恢复且旧审计可重建；不把内部实现细节变成用户额外操作。本轮只设计，不替用户改实际错误金额。

## 2. 金额显示统一

所有用户可见金额包括统计卡/均价、成员及团体花费、记录列表/详情/核对、券列表/批次/流水/详情、赠送、交换继承及成本更正预览，统一显示四舍五入到元。例：内部93.75显示94元，37.5显示38元；任何前台位置不再显示“375/4”。

金额输入和保存继续允许小数；不把界面的整数回写为新的原金额。求和、均价、赠送和交换继承均用未舍入金额，最后才格式化；不先把每张取整再相加。沿用无二进制误差的现有精确计算是兼容方案，不要求为了显示把历史数据强制转成double。比例属于内部旧数据/审计编码，不能直接暴露为金额文本。

面向用户的统计金额列采用与界面相同的元显示；如既有精确业务导出列需保留小数，改为十进制表示并在实施前固定其精度/往返测试，不把循环小数截断值当完整恢复真值。完整备份、技术携带及原始审计保留恢复所需原值和历史编码；用户要求去分数显示不作为损坏旧备份或全库改存储类型的理由。

## 3. 花费只展示现有金额

- 已知100元且另有缺失记录，显示“花费：¥100”，不加括号、缺失数量、未知提示或解释段。
- 一部分来源成本未知时只汇总已知贡献，不猜价格；均价仅用有金额的对应数量，去“已知成本”等界面措辞，使用“均价”。
- 全无金额时不显示花费金额行/金额卡；保留记录、成员、团体和张数等已有信息，不把这些对象从列表删除。只在整个页面确无记录时用普通空状态。
- 明确填写0与未知不同：明确0显示0元；未知仍为空，不能为简化界面写成0或默认成本。
- 去除普通花费视图中的“另有金额未填写”“金额未知，未进入均价分母”“金额保留精确值……”及同类常驻说明；内部仍保留可空、来源及审计事实。
- 用户正在提交无效金额、缺少真实库存动作必要字段或更正链校验失败时，仍保留具体操作错误提示；这与统计区的常驻缺失说明分别处理。
