# 统计时间筛选：今日、日历与月年切换

2026-10-21仅记录、评估及排期，合入尚未开发的 **v1.5.1-r4 / M5 / 产品1.2.0**，保留原停用来源区分完整范围。r4仍为下一唯一本地工作包，依赖已交r3；估算由1–2调整为 **2–4人日**，M5本段16–28、主线累计64–109人日。拟1.2.0-rc.10/code至少15014，仅计划，无新APK；定时PAUSED保持。

用户原意：统计时间筛选增加“今日”，日期输入改成日历点击选取，并加入切换月/年的按钮。

## 现状评估

`bi_page.dart`已按日/周/月/年/所有显示范围选项，也有“上一期间/下一期间”箭头。点期间标题调用`_chooseDate`，实际是`_BiDateDialog`中的YYYY-MM-DD文本框，没有日历或今日快捷入口。同一日期弹窗被成员每日查看复用。`bi_query.dart`的`BiPeriod`已负责范围边界和按日/周/月/年步进，可继续使用，不增加第二套日期统计算法。

## 规划行为

1. **今日**：在现有范围选项旁增加可点的“今日”快捷选项。点击时重新取得现有业务时钟的上海当天日期，设为日范围；保留团体、成员、属性等其他筛选，不清空它们。它是日范围的快捷操作，不新增存储或独立统计口径；手动选择今天亦可显示选中态。停留跨日后再次点击应定位新的一天。
2. **日历选日期**：点期间日期打开日历，点选日子后确认生效；取消、系统返回均保留原筛选。默认进入当前锚点日期，主筛选选择日期后保留原日/周/月/年范围；“所有”沿原规则无日期限制、日期入口禁用。主流程不要求手输YYYY-MM-DD，避免日期键盘。
3. **月/年切换**：日历提供上月/下月按钮及清晰的年份选择入口，能先切年再切月选日；打开日历与翻页不立即修改统计，确认才更新。统计主筛选保留现有月/年范围选项；月范围的导航明确为“上月/下月”，年范围为“上一年/下一年”，点击按对应期间切换，标题同步显示所选年月。日/周原步进保持，不额外增加一排含义重复的按钮。
4. **共用入口**：管理“报表与导出”使用同一个BiPage时间控件，同步获得日历和今日入口，保留其独立筛选状态。成员每日查看复用日历时继续限制在当前期间内，不让选日越界；统计到成员/团体花费及原记录下钻仍携带已选期间。已移入管理的报表/CSV不因此重新显示到统计主页。

今日点击即生效、日历选日确认后生效，是本轮可逆交互方案；月/年按钮按上述日历导航和期间导航两层表达。布局实施后待用户检查，不为此改变现有周界、时区、统计发生日或库存截止政策。

## 依赖与实施边界

原停用来源分支与本时间筛选分支均不需数据库迁移，汇合一次r4验证和正式候选。各分支先共享只读状态/日期模型，再接消费者和页面，最后同包回归。不得以新增日期需求缩掉停用来源四组合或历史保护。

预期文件：`lib/cheki/ui/bi_page.dart`及必要日期控件、`lib/cheki/data/bi_query.dart`的必要导航适配、相关BI/widget测试和UI说明；成员日视图与管理报表共用消费者一并审查。优先复用锁定Flutter工具链的日历能力，不因换输入另建日期引擎或随意升级依赖。

本轮不改Dart/配置/原型，不运行产品构建或设备操作。实施不改原记录日期、ID/动作戳/NULL/原文、库存或成本，不向历史记录补今天，不新增持久化筛选字段。
