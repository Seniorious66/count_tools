## 1. 统计页减负，低频报表移到管理

用户指出统计中的“购券与成本”“库存”和保存CSV不常用，允许移到管理折叠。本包采用保留能力、移走入口：统计主页不再铺开购券成本、库存报表或显示保存统计CSV按钮及其说明。中间的“期间券流水”与这些券报表同组移入，避免只移两端仍留下券报表残段；这是同一券报表组的整理，不删除流水。

管理增加默认收起的“报表与导出”，展开后可进入购券与成本、期间券流水、库存及统计/花费CSV导出。统计主页保留Cheki张数、成员/同人、每日张数、饼图、尺寸属性和成员/团体花费入口。花费页面的CSV按钮也统一收至该管理区，查看花费和原记录仍可直接操作；完整备份、恢复及结构化数据携带不受影响。

现状：`bi_page.dart`把报表区、CSV和核心BI串在一个列表；`spending_page.dart`另有花费CSV；`catalog_pages.dart`管理页无报告容器。实施先拆共享报表内容/筛选与导出，再接管理导航，不能复制一套计算规则或删查询接口来隐藏UI。

报表页使用现有BiStore/BiReport和金额口径，保留日/周/月/年/所有、日期锚点及适用团体/成员等筛选。由管理独立进入默认当前月、所有团体，明确显示本页范围；库存显示原截止日期，不冒用统计页旧缓存或把当前月库存当当月新增。导出采用管理报表页当前可见范围及筛选，已知金额舍入/十进制列规则保持。CSV仍由系统文件选择器显式保存，取消不修改账本、不自动写手机常驻文件。

## 2. 隐藏旧档案两个入口，保留可恢复能力

管理里的“旧版项目”和“旧档案映射”默认不显示，也不改名后挪到另一处常用页面。用户确认以后不再补旧档案，未来需要时再明确调用。

仅调整入口可见性；旧页面、映射逻辑、表、原始行、稳定ID、历史原文、附件、备份及恢复兼容全部保留。用单一内部入口开关默认关闭，或同等可逆导航边界；不新增面向用户的开关、密码、隐藏手势或额外管理步骤。以后用户明确要求时再开放对应入口或经既有受控流程调用，不把本次隐藏解释为删除旧数据或永久取消恢复能力。已映射Cheki继续正常展示。

现状：管理页直接构建旧版HomePage与LegacyMappingPage入口。隐藏只影响导航，不得顺带将旧数据从快照、恢复或统计中剔除。

## 3. 首页及记录页统一左右三行卡片

用户要求将当前纵向五行压到正常字号约三行高度，解决右半空置：

| 左侧，约60% | 右侧，约40% |
| --- | --- |
| 日期 | 张数 · 尺寸 |
| 放大的成员名称，占后两行高度 | 属性/背签 · 领取状态 |
| 名称区域的第二行 | 花费金额（有金额才显示） |

日期保持较小字号；成员名建议正常字号20–22sp，占一个可容纳两行的区域，单个短名不人为拆字，长名可换行。团体前缀/标签、成员设置色必须保留；多人合影以两行可读摘要及人数提示呈现，原详情与辅助技术保留完整成员。不是把所有成员和长团名挤进不可读的一行。

正常字号卡片以三条右侧信息为高度基准，初始目标约96–112逻辑像素（含上下内边距，实际以字体测量复核）；左侧日期一行+成员两行。右侧文字右对齐、基线一致，内部列间距建议12、卡内边距12。宽度按可用空间分配，右侧金额或属性较长时允许调整列比或增高，不能裁掉金额、领取或背签，也不能靠缩字强行塞入。未知金额继续隐藏，全未知不补0；明确0仍显示。

现状：首页最近记录、记录列表与合并原条页共用`record_browse.dart`的`_RecordTile`，目前Column逐行堆日期、每个成员、数量尺寸、属性领取、成本，合并时还加“n条记录”。应先提取/调整共用摘要组件，同步首页与记录页；附加的原条数量不另占第四行，可置摘要辅助位置或原详情。合并仍是可逆显示，保留原ID和展开编辑能力，金额继续同源，不改变统计、排序、筛选或真实行数。

窄屏/200%字号/多成员/长金额下允许卡片增高、必要时纵向回流；正常字号以三行左右布局验收，大字不能按固定高度裁切。点击、返回、修改后的刷新保持。

## 4. 券库两列紧凑网格

一张卡对应一个券种，不按每笔购券生成卡、不合并不同券种。券库正常字号每行两卡，按原可用库存降序从左到右、再到下一行排列；库存变化后刷新排序，同库存保持既有稳定次序。保留顶部购券/新增券种/临期设置及可用券摘要，与网格有明确间距。

初始网格参数：左右页面边距16、列间距12、卡内边距12。每卡宽度为`(屏宽 - 32 - 12) / 2`：

| 逻辑屏宽 | 每卡宽 | 卡内文字宽 |
| --- | ---: | ---: |
| 320 | 138 | 114 |
| 360 | 158 | 134 |
| 390 | 173 | 149 |
| 430 | 193 | 169 |

卡内优先级：第一块团体或团体-成员名（正常字号最多两行，完整名称可由语义/详情读取）；其下尺寸/带签属性等辨识信息，再突出可用张数；停用、过期、临期及实际限时信息按原规则可见。仅长期不标长期，无限时库存不展示限时0。限时与长期同时存在才区分各池；限时实际日期/风险不能因紧凑隐藏。点整卡仍进入原券详情，原四个操作不改。

现状：`TicketLibraryPage`使用ListView逐个全宽ListTile，`stockOrderedDefinitions`已有降序逻辑，`poolWidgets`承载期限和可用量。实施应复用读模型和池规则，先做紧凑卡内容测量，再改网格容器；不要把两个全宽ListTile硬挤到一行或使用会截内容的固定宽高比。相邻卡对齐，行高能容纳本行内容。正常字号两列；大字/超长内容无法安全容纳时允许自适应一列，不能缩字或溢出。券种管理的编辑列表与草稿保持原用途，不顺带将管理页所有列表改网格。
