# 14001 实机反馈修复规格 · 2026-10-14

来源：用户覆盖安装后提出的10项问题、购券核对失败截图，以及追加的记录页入口与筛选要求，共11项。唯一排期来源仍为 MasterSheet。新增工作包 **v1.4.0-r2 / M3 / 产品目标1.1.0**，位于 v1.4.0-r1 后、M3检查点和 v1.4.1 前；本轮只有分析和规划，没有实施。

## 已查明与待验证

1. 管理页的「旧版项目」「Cheki记录」「成员」等 ListTile 显式零内边距，「券种管理」「备份与恢复」仍用默认内边距，造成文字起点不齐。
2. 首页数量共享双栏，但购券只有右侧一个独立按钮，左侧新增又在下方「记一笔」，行动区并不对称；未领取卡没有零值隐藏条件。记录页仍有可关闭合并的开关及新增加号和旧补录筛选。
3. 当前 `recordCostsIn` 只查询真实券消费绑定，旧数据无此绑定，因此旧金额未显示。旧值并未丢失：22:28安装前的既有完整快照只读分析，342条原记录的 `price` 都是可解析数额，合计 **27355**，其中 **70条明确为0**；`legacy_raw.price` 及稳定原ID保留。例如糕2025-06-26的两条各100，合并金额应200。这是已保存快照，不能称本轮手机实时数据。
4. 新购券表单日期初始化为空、期限没有默认、posted默认为false；用户截图显示2张、160、惑星-船儿、长期及确认入库，但没有日期。后台校验将缺日期、缺期限和金额冲突等合并为同一个 FormatException。**缺日期是目前高度吻合的原因**；截图不足以证明具体运行值或排除其它校验条件，实施时必须隔离复现再闭环。
5. 编辑页和券控制器各自读取身份目录，详情/核对为名称又加载全记录读模型；保存后的广播会让多个页面刷新。关联保存还执行包含历史原档的完整联动验证。这些是源码可见热点，**不是已经测出的卡顿根因**；本轮未连接设备、计时或复现性能。

## 单一金额契约与兼容

用户新确认「以前的都按照旧纪录的数额算，新纪录也只保留数额，但是关联券的数额」明确了旧price的业务含义，优先于之前为了避免猜测而未读取旧金额的边界。旧决定和旧交付的当时结论保留，新增 DEC-062 记录当前规则。

- 指定旧记录金额优先读取自身稳定来源ID对应的 `legacy_raw.price`，必要时用同快照原表及明确来源映射补读取；不按姓名/日期猜配，不把342条以外记录强行配旧金额。来源有冲突、缺失或非法原文时留空并给隔离差异清单，保留原文，不能猜0。
- 342个明确旧金额作为该条Cheki花费，不能生成虚构购券/消费、改变库存、把它乘张数或参与人数，也不能再加一遍券成本。合并按原ID去重逐条加金额；100+100=200，明确0仍是有效已知金额。
- 新记录花费来自实际关联消费的冻结来源分配之和；不是券种标价、购券整批总额或现价。仅修改备注/领取不重算；改变实际券关联需要预检及原子审计，对下游保持已有纠错边界。未知来源金额仍未知。
- 旧记录和新记录同一花费展示/汇总/普通导出，保留内部金额来源和精确比例供审计与恢复。已知部分不能冒充完整数额：合并或统计有未知金额时在辅助信息标明缺失，金额不显示伪造完整总和。购买付款、实际Cheki花费和库存成本是不同指标，各自统计，不把旧Cheki金额当作库存购买历史。
- 新购券只提供总金额输入，单张来源成本在内部按总金额/张数精确派生；已有unit_price原文、未知字段、历史和扩展导出/完整备份仍保留。金额舍入、整数分或余分政策没有因删除单价输入而自动批准，沿用原文与精确比例。总金额100/3张内部保留精确比例，不静默舍入；页面可显示精确数额，如10/3，不再多字段重复说明。
- 优先使用只读兼容金额解析，避免需要整代恢复或改写342条历史。若实施确实新增持久化信息，只追加可空字段/审计与备份恢复兼容，隔离往返先验，不能把本规划当成真实批量写入授权。所有业务可空继续有效，移除两个旧筛选入口不收紧存储契约。

## 性能验收与顺序

金额读模型及购券默认/校验 → 单次编辑读写与性能定位 → 管理/首页/记录/券详情布局 → 跨页金额统计/CSV与兼容恢复。它们共享金额和事务契约，放同一修复包，v1.4.1再冻结携带模板。

用标记的合成库与隔离副本测343条/1050修订级别、5000条/多次修订级别；同一运行环境至少10次温启动操作，报告P50/P95及冷加载，区分宿主结果和S25结果。初步目标：触摸后100ms内有导航或忙碌反馈；343规模温态打开修改P95≤800ms、仅记录保存并回列表P95≤1s，5000规模≤2s。扣券预检另分段报，不能用后台未提交先显示成功掩盖慢操作；若目标未达成，提交实际耗时、剩余热点与下一步，不写性能已通过。Android实际目标仍需后续设备授权确认，定时轮不得借机连接手机。
