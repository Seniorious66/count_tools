## 现状与范围

- `lib/cheki/ui/ticket_pages.dart` 的TicketEditPage用于购券和库存调整；限时池截止字段提示`YYYY-MM-DD`，普通文本键盘，Controller直接组装TicketInformation。
- `lib/cheki/ui/transfer_pages.dart` 的TransferEditPage分别持有来源、目标截止日，自动选池和手动池比较以内部完整日期匹配。只换提示文字会导致六位值被领域校验拒绝或匹配不到原池。
- TicketInformation和OccurredOn校验实际完整日期；原库、FIFO和池身份依赖规范`YYYY-MM-DD`。因此本次修改放在共用表单输入适配边界，不能全局放宽领域日期或变更存储格式。

## 计划行为

1. 所有限时券截止日期的手动输入统一六位数字`yymmdd`，不要求输入横杠；例如`261231`表示2026年12月31日。购券、库存调整、换券/送券的来源及目标截止输入共用规则。使用数字键盘，提示采用`截止日 YYMMDD`及六位示例，不自动插入横杠。
2. 六位年暂按`20yy`解释，范围2000–2099，作为可逆输入边界记DEC-093；不使用随当前年份变化的滑动窗口。原有其他世纪的日期保留完整年份兼容读回，未改日期时不重释，不强制转换/截断旧年份；未来若需输入其他世纪另行决定，不推测用户意图。
3. 严格校验长度、数字、月份、当月天数与闰年。`280229`有效；`260229`、`261332`、五位/七位、负号或分隔符等应给截止字段的具体提示，不能让DateTime自动溢出成其他日期。不自动填今天或猜缺失日期。
4. 通过校验后，统一转换为内部规范日期，再参与信息组装、来源池匹配、自动选择和核对保存；读取规范旧日期时在可表示范围内显示六位，核对与最终保存指向同一天，不改变日期含义。
5. 长期券仍没有截止日期，默认长期及自动记录日期保持；不能把此次格式变更扩大到购券录入动作戳、Cheki发生日期或统计日历。已有限时券的日期、截止日包含当天、FIFO及成本谱系均不变。
6. 原ID/created_at/ext/原文/缺键NULL/未知字段及审计保持。编辑旧券打开、取消或仅改无关字段，不将展示格式当作日期变更，不额外修订流水；历史空日期保持空。可空草稿与实际入账需要已知截止日的现有校验各自保留。
