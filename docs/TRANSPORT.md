# 结构化数据携带

v1.4.1 / M4 新增「管理 → 数据导入与导出」。它和统计页的阅读型 CSV 分开：统计 CSV 用于查看结果，多表数据包用于携带完整账本。原「备份与恢复」继续兼容旧版 `.chekibackup`。

## 操作与两种模式

1. 选择「交易追加」或「完整账本快照」，导出完整数据包；或导出空交易模板。
2. 文件只保存到系统文件选择器中主动选择的位置，不自动写入下载目录、NAS或云盘。
3. 导入时选择对应模式及文件，先检查格式、稳定 ID、引用、时间、成本来源和库存。错误整批拒绝，当前账本保留。
4. 查看当前与导入后团体、成员、记录、券、换送、设置和文件数量。确认预览后还有一次明确确认；取消不提交。导入前账本变化会使预览失效。

**交易追加**只增加稳定 ID 尚不存在的完整对象及其关联、操作和修订。相同 ID、相同内容跳过；相同 ID、不同内容整批拒绝，不覆盖、不按名字匹配。无稳定主键或含NULL主键的扩展行按相同内容的实际行数逐一匹配，只能保持已有行；额外同内容行也不能静默跳过；设置同键不同值、附件同路径不同内容、表结构不同均拒绝。批次有独立 ID 和内容收据，相同批次不得换内容重用；重复提交不重复购买、扣券或计算成本。新增业务行仍须包含有效审计及引用，全批校验后才提交。

**完整账本快照**恢复文件中的整个账本，而非把其库存叠加到现有账本。数据含全部历史及成本来源，因此无须再单独回放其购买或消耗。生成时间记录为 `captured_at`，业务发生日、未来交易、领取时间及动作时间仍按各原始字段保存，不由导入时间替代。恢复前的完整代保留，失败或中断使用既有持久事务回滚。

**DEC-015 仍待用户检查**：首版采用上述可逆保守规则，并未决定通用余额快照截至日、历史截断或覆盖合并规则。仅有「截至某日剩余几张」的库存汇总，缺少历史成本来源，不能自动转换成购买/调整流水，也不能和历史交易累加。XLSX、名字自动匹配和对已有对象的批量覆盖尚未开放。通用旧库语义映射属于下一包 v1.5.0。本轮不实施真实历史批量导入或手机迁移。

## 数据包契约 v1

扩展名 `.chekicsv.zip`，内容为 UTF-8 多表 CSV 和清单，无运行脚本或可执行 SQL：

| 文件 | 内容 |
| --- | --- |
| `manifest.json` | `format=cheki-csv-tables`、version=1、schema=8、mode、batch_id、captured_at、template、tables |
| `tables/NNN.csv` | 一张实际 SQLite 表；清单记录原表名、列顺序和主键。实体、同人关系、Cheki、领取、券、购入、库存成本分配、换送、复合绑定、全部修订与操作、旧四表、迁移账本、序列及扩展表均覆盖 |
| `seed.chekibackup` | 经完整恢复检查的结构/原始档案载体，含数据库、设置、附件及适用事务附属文件；不能删除。导入不执行 CSV 提供的 DDL |
| `README.txt` | 模式、编辑和空值说明 |

CSV 遵循引号、逗号、CRLF及引号内换行规则，允许 UTF-8 BOM。每个单元格再使用 JSON 值区分类型：`null` 为数据库 NULL，`"001"` 是文字，`2` 是整数，`{"$blob":"AP8="}` 是二进制。`information_json` 等列是原始 JSON **文字**，本身再编码为 JSON 字符串，内部原有缺键、NULL、未知键、空列表、数值原文和时间原文不重建、不套新建默认。公式开头的文字也保留为 JSON 字符串，不输出为可执行电子表格公式。

空模板各 CSV 只有表头，结构载体清空用户行并压实数据库，仅保留迁移账本和固定初始尺寸，不含设置或附件。模板本身不能当完整快照恢复。不能把模板理解成可以任意省略动作所需的技术关联；业务信息可以为空，内部 ID、动作时间、引用和审计仍须有效。

ZIP 首版支持普通单盘、无加密的 stored/deflate 文件，拒绝重复/大小写冲突路径、越界路径、符号链接、异常 CRC、大小不符、未知文件、重复 JSON 键及表/字段清单变化。总包及展开内容上限均为 128 MiB，最多 2048 项；ZIP64、数据描述符、目录条目、注释及特殊压缩方式不在首版范围。重新打包应仅包含上述文件，保留相对路径。触发器或虚拟表不经 CSV 执行，遇到这些扩展须使用原完整备份恢复。

扩展表的外键同样整批检查；无主键/NULL主键的重复行在完整快照中保留全部份数。序列不能低于原档案或已有最大 ID，事务合并取安全高值；不重编号业务对象和历史。金额保持旧原文/精确比例，指定旧 price 与新关联券冻结金额仍由现有同源查询读取，传输不另算价格、不舍入、不制造旧库存。

## 实现与恢复

`TransportStore` 在独立、受控目录解析和组合候选，完整 `StorageSchema.validate` 通过后交给 `BackupStore.prepare/apply`；预览绑定捕获时的当前代指纹，防止组装期间新增数据被覆盖。事务、设置及附件一起切换，不在当前账本逐表试写。取消或完成后的自有工作副本可清理，历史完整代和中断事务材料保留。

本包保持 schema 8，未改变旧模型或原生备份格式；只增加版本化携带协议与内部批次收据文件。旧备份仍可检查、隔离迁移及恢复。新协议不把未来或不同 schema 的结构直接解释为当前模型。

验证包括合成全模型往返、完整成本谱系、空值/缺键/未知字段/BLOB/序列/设置/附件、重复批次/内容冲突、错误关联/日期/数量、过期预览、三处事务故障回滚、Python ZIP 互读、独立 Dart 进程读取 deflate 包，以及 Python 完整恢复和真实子进程中断恢复。具体实际结果见本包交付材料；本地证据不能替代 Android SAF、原位升级、实机冷启动和交互验收。
