## v1.1.1 完整备份恢复

本地工程入口已实现并验证，操作见 [恢复指导](../RECOVERY.md)。当前 App 尚无面向日常使用的备份恢复页面，该页面属于 M2。

| 检查 | 预期 | 实际 |
| --- | --- | --- |
| 全库与设置 | 全字段、ID、NULL、未知值、序列、设置和附属文件等价 | 13 项隔离测试通过，覆盖未知表/BLOB/索引/视图和序列、Android XML/偏好 JSON 原始字节 |
| 一致 SQLite 快照 | 包含已提交 WAL，排除尚未提交事务 | 合成 WAL 场景通过；源库只读，不做源 checkpoint |
| 预检/预览 | 损坏、无效业务关联、未标记目标拒绝；预览不改原代 | 校验与前后逐文件比较通过，私密值不进入输出 |
| 故障回滚 | 数据库与设置共同回到原代 | 旧代移动后、新代切入后的故障均回退；失败暂存保留 |
| 进程退出恢复 | 新进程能读取事务标记并恢复原代 | 两个切换点实际子进程退出，新进程 recover 成功 |
| 旧系统副本往返 | 原导出不改，完整恢复再导出仍一致 | 10:27 历史快照的 1 项目/25 子项目/342 明细、6 个设置、序列与 android_metadata 等价；journal/manifest/profile 附件相等；新进程重开核验通过 |
| 原双备份保护 | E 与 NAS 原完整快照仍相同 | 12 原文件两处一致；本次工程操作后 E 原快照逐文件不变，没有重新读取手机 |

可复查的隔离产物在仓库外 `artifacts/count-tools-recovery/m0-v111-ae004d9a`：`backup`、`isolated/current`、`roundtrip-backup` 及内部核验收据。它们保留私人数据，不提交 Git。M0 的通用自动验证只使用合成数据，不依赖这个个人目录。

失败记录：源目录保护使首个 XML 样本位置不合规，移动合成样本后通过；XLSX 首次写入新日期采用标准 ISO 日期类型，原检查器只理解数字日期而失败，已兼容该类型并增加历史等价与非法日期负例。最新流程回归为 27 项；v1.1.0 当时的 25 项历史证据保留。
